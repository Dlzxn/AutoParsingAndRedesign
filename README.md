# Найти клип — поиск коротких видео и онлайн-редактор клипов

**Сайт:** https://naitiklip.ru

Веб-сервис для авторов коротких видео: находит ролики на популярных площадках и превращает их в готовые
вертикальные клипы прямо в браузере.

- **Поиск по тегу:** VK Клипы, YouTube Shorts, Coub, Reddit, Imgur; текстовые посты Tumblr.
- **Без повторов:** просмотренные и скачанные ролики больше не попадают в выдачу пользователя.
- **Скачивание** в MP4 (H.264 + AAC) со звуком; файлы называются по заголовку ролика.
- **Редактор клипов:**
  - обрезка, скорость 0.25–4×, плавное появление и затухание;
  - форматы 9:16 / 1:1 / 4:5 / 16:9 — обрезка, размытый фон или поля; поворот, отражение, разрешение до 1080p;
  - яркость, контраст, насыщенность, чёрно-белый режим;
  - подписи на кириллице с цветными эмодзи (подложка или обводка), логотип с прозрачностью, субтитры `.srt`;
  - громкость, фоновая музыка (поверх или вместо звука), три уровня качества.

  Превью всех настроек — мгновенно в браузере и совпадает с результатом; рендер идёт в фоне через ffmpeg
  с прогрессом. Готовые ролики хранятся в «Моих роликах» 24 часа.
- **Светлая и тёмная тема** (по умолчанию светлая, выбор запоминается).
- **Админ-панель:** пользователи, тарифы, промокоды, включение/отключение площадок, статистика, выгрузка в CSV.

## Стек

FastAPI · SQLAlchemy 2 (async) · Alembic · PostgreSQL (SQLite для разработки) · ffmpeg · Pillow · yt-dlp ·
aiohttp · Jinja2 + чистый JS без сборки · Docker · Caddy (автоматический HTTPS).

## Разработка

Нужны Python 3.12+, ffmpeg (вместе с ffprobe) и Node.js или Deno (yt-dlp использует их для YouTube).
Для цветных эмодзи в подписях нужен системный шрифт эмодзи: в Windows он есть по умолчанию, в Linux —
пакет `fonts-noto-color-emoji` (в Docker-образе ставится автоматически).

```bash
python -m venv .venv
.venv/Scripts/activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env            # заполнить ключи площадок
python -m app.cli create-admin admin@example.com 'сложный-пароль'
uvicorn app.asgi:app --reload
```

Без `DATABASE_URL` используется SQLite (`var/app.db`). Миграции применяются автоматически при старте.
Документация API в режиме разработки (`DEBUG=true`): `/api/docs`.

## Деплой

Сервер: Ubuntu 22.04+ с доступом по SSH, открытые порты 22/80/443. Скрипт сам ставит Docker, создаёт swap,
настраивает firewall, поднимает приложение, PostgreSQL и Caddy с бесплатным сертификатом Let's Encrypt.

**Требования к серверу:** минимум 2 vCPU / 2 ГБ RAM / 30 ГБ SSD (один рендер за раз);
комфортно — 2 vCPU / 4 ГБ, при росте нагрузки — 4 vCPU / 8 ГБ и `RENDER_WORKERS=2`.

### Первый запуск

1. Создайте `deploy/.env.production` по образцу `.env.example` (ключи площадок, `ENVIRONMENT=production`,
   `COOKIE_SECURE=true`, `RENDER_WORKERS=1`). Файл не попадает в git и загружается на сервер один раз —
   там он лежит в `/opt/autoparsing/.env`. Пароль PostgreSQL генерируется автоматически.
2. Для своего домена добавьте у регистратора A-записи `@` и `www` на IP сервера.
3. Запустите:
   ```bash
   ADMIN_EMAIL=you@example.com ADMIN_PASSWORD='сложный-пароль' \
     bash deploy/deploy.sh root@IP_СЕРВЕРА ваш-домен.ru
   ```
   Без домена сайт будет доступен по адресу `https://IP-С-ДЕФИСАМИ.sslip.io`.

### Обновление

Закоммитьте изменения и запустите `bash deploy/deploy.sh root@IP_СЕРВЕРА`. Скрипт соберёт архив из git,
пересоберёт контейнеры и проверит, что приложение поднялось. База, медиафайлы и `.env` сохраняются.

Чтобы сменить домен, передайте новый вторым аргументом — старый адрес и `www` будут перенаправлять на новый.

### Эксплуатация

На сервере все команды выполняются из `/opt/autoparsing`:

```bash
alias dc='docker compose -f docker-compose.yml -f deploy/docker-compose.prod.yml'
dc ps                                   # состояние контейнеров
dc logs -f app                          # логи приложения (а также caddy, db)
dc exec app python -m app.cli create-admin email 'пароль'   # администратор / смена пароля
dc exec db pg_dump -U autoparsing autoparsing | gzip > backup_$(date +%F).sql.gz   # резервная копия БД
nano .env && dc up -d                   # изменить настройки (например, VK_ACCESS_TOKEN) и перезапустить
```

Проверка состояния: `https://ваш-домен/healthz` (БД и ffmpeg).

Приложение работает **в одном процессе uvicorn**: очередь рендера живёт в процессе, а сам ffmpeg и так
использует все ядра. Одновременных рендеров — `RENDER_WORKERS`.

## Ключи площадок

| Переменная | Где получить |
|---|---|
| `YOUTUBE_API_KEY` | Google Cloud Console → YouTube Data API v3 |
| `IMGUR_CLIENT_ID` | https://api.imgur.com/oauth2/addclient |
| `REDDIT_CLIENT_ID`, `REDDIT_CLIENT_SECRET` | https://www.reddit.com/prefs/apps (тип script) |
| `TUMBLR_API_KEYS` | https://www.tumblr.com/oauth/apps (consumer key; можно несколько через запятую) |
| `VK_ACCESS_TOKEN` | пользовательский токен VK с доступом к видео (VK ID) |

**VK:** без `VK_ACCESS_TOKEN` поиск идёт через Google и headless-Chrome, а Google часто отвечает капчей.
В продакшене образ собирается без Chromium (`INSTALL_CHROMIUM=false`) ради экономии памяти, поэтому VK
работает только с токеном; без него площадку стоит отключить в «Админка → Платформы».

## Перенос данных со старой версии

Старая версия хранила пароли открытым текстом, историю клипов — в `Data/clips_history.json`, тарифы
и статусы площадок — в JSON-файлах. Чтобы перенести всё в БД:

1. Укажите в `.env` `DATABASE_URL` старой базы PostgreSQL (сделайте резервную копию!).
2. Положите в один каталог `clips_history.json`, `tarifs.json`, `platforms.json` из старой версии.
3. Выполните `python -m app.cli import-legacy путь/к/каталогу`.

Команда применит миграции (существующие таблицы `users` и `promo` сохраняются), захеширует все пароли
и перенесёт историю, тарифы и статусы площадок. Повторный запуск безопасен. Пароли старых пользователей
продолжают работать.

## Тесты

```bash
pytest                                   # всё: бэкенд, реальный рендер, JS, браузерные сценарии (~5 минут)
pytest -m "not ffmpeg and not e2e"       # быстрые тесты без рендера и браузера (~40 с)
pytest -m e2e                            # сквозные сценарии в настоящем Chrome
pytest -m live                           # проверка реальных API площадок (нужен .env с ключами)
pytest --cov                             # с отчётом о покрытии кода
TEST_DATABASE_URL=postgresql+asyncpg://user:pass@localhost:5432/test_db pytest   # на PostgreSQL
```

479 тестов, покрытие бэкенда 99%:

| Слой | Где | Что проверяется |
|---|---|---|
| Площадки | `tests/search/` | разбор реальных ответов API, пагинация, ключи, лимиты, ошибки, VK через браузер |
| Поиск | `tests/search/test_service.py`, `test_search_api.py` | кэш, таймауты, объединение запросов, история, права |
| Редактор | `tests/editor/` | команда ffmpeg, реальный рендер всех функций, текст с эмодзи, очередь, отмена, ошибки |
| Приложение | `tests/test_*.py` | авторизация, админка, страницы, миграции старой БД, CLI, healthcheck |
| Фронтенд | `tests/js/`, `tests/test_frontend_js.py` | JS-функции (node:test), совпадение превью с рендером на 480 комбинациях |
| Браузер | `tests/e2e/` | регистрация, поиск, монтаж от начала до скачивания, тема, админка, мобильная вёрстка |

Тесты, которым нужны ffmpeg, Node.js или Chrome, автоматически пропускаются, если их нет.
`TEST_DATABASE_URL` — отдельная пустая база: она очищается перед каждым тестом.
